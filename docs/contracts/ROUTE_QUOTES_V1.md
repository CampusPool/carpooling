# Route quote and fixed-date offer contract v1

20 October 2026. S2 implementation specification. This is original product behavior; neither provider availability nor physical stop suitability is established by this contract. Further authentication work is deferred by the user; reuse existing access checks.

## API

All routes require an active, unbanned approved member of the configured college, even when legacy cohort enforcement is disabled for tests. Missing college configuration fails 503. Responses use `{"data": ...}`; errors use `{"error":{"code":"..."}}`. No provider bodies, secrets or SQL errors are exposed.

- GET `/api/mobility/pickup-points`: bounded `page_size` (1..50, default30), `after` positive ID, optional `vehicle_type` bike/car. Returns active operator-verified Bengaluru catalog points with ID, version, name, lat/lng, supported modes and next_cursor. Empty catalog is valid; no invented production stops.
- POST `/api/mobility/routes/quote`: exactly `pickup_point_id`, `dropoff_point_id` (distinct positive integers), `vehicle_type` bike/car. Ignore no dangerous extras: reject geometry, distance, fare and unknown payload fields with422. Server resolves catalog and canonical node identity. Car/bike profiles are separately configured; no implicit public demo/fallback. Response201 `data` contains opaque id, vehicle_type, provider, profile, points (ordered canonical point objects), distance_meters, duration_seconds, currency=INR, seat_price_minor, pricing_version, expires_at (UTC ISO), synthetic_only boolean.
- POST `/api/mobility/pool-offers`: exactly `quote_id`, `car_id`, `trip_date` local `Y-m-dTH:i` in Asia/Kolkata, `total_seats` (1..5; bike exactly1), optional description (max600). Header Idempotency-Key is required (8..128 visible ASCII characters). Unknown fields rejected422. Departure must be >now+15min and <=now+30days. Response201 `data:{id,existing:false,quote_id,currency,seat_price_minor,vehicle_type,synthetic_only}`; same owner/key/payload returns200 with existing=true even after quote expiry; different payload409. Same consumed quote/new key409; wrong owner404. A current invalid account/member or exact vehicle approval still denies retries. The canonical Trip/TripPoints/Route rows remain booking authority.

## Shared schema and worker boundary

Routing worker owns migration `2026_10_20_000200_create_mobility_routing_tables.php` and `Mobility/Routing/` except OfferController, OfferService, TrustedRouteContext and associated offer tests. Coordinator owns route registration and service provider changes.

`mobility_pickup_points`: unsigned bigint id; college_code string64; canonical_node_id unsigned int referencing nodes_geo; version unsigned integer; name string160; lat/lng decimal(10,7); vehicle_modes JSON list; active boolean; verified_at nullable timestamp; synthetic_only boolean defaultfalse; timestamps. Points must be within the explicit approximate Bengaluru development envelope lat12.70..13.30/lng77.30..77.90; this is a routing scope bound, not evidence of operating permission or safe pickup. Normalized canonical point is `{address:name,json_address:{id:canonical_node_id,name:name},lat:float,lng:float}`; canonical node coordinates/name must match. No client node IDs accepted.

`mobility_route_quotes`: id UUID primary; user_id unsigned int; college_code string64; snapshot JSON; expires_at timestamp; consumed_trip_id unsigned int nullable; timestamps. Immutable `snapshot` keys exactly mirror the quote response except id/expires_at, plus `pickup_points:[{id,version,canonical_node_id},...]` in order. `points` are canonical normalized points. Expires after5min. Provider I/O occurs before a short transaction rechecks actor/catalog snapshots and inserts the immutable quote. Provider calls never run under admission/quote locks. Avoid logging precise coordinates or provider payloads. A quote is not a seat reservation or collected money.

Offer worker owns migration `2026_10_20_000300_create_mobility_pool_publications.php`: id bigint, user_id unsigned int, key_hash char64, request_hash char64, quote_id UUID unique, trip_id unsigned int unique, timestamps; unique(user_id,key_hash). It also owns OfferController, OfferService, TrustedRouteContext, offer tests and a minimal `backend/integrations/carpoolear/routing-integration.patch`; coordinator integrates patch preparation/route registration. Quote snapshot interface above is authoritative. Workers may read each other's files but do not edit them.

## Provider and pricing configuration

Laravel config keys `mobility_routing.car_base_url`, `.bike_base_url`, `.car_profile`, `.bike_profile`, `.provider` (=osrm), `.pricing_version`, `.car_minor_per_km`, `.bike_minor_per_km`, `.synthetic_only` (defaultfalse). Environment mapping belongs to coordinator/provider registration. No URL/profile/rate/version default that implies a real provider or approved fare. `synthetic_only=true` permitted only testing. URL is operator configuration, never user input; bounded HTTP connect2s/total5s, redirects disabled, no retry flood, strict successful OSRM Ok response, positive finite bounded meters/seconds, sensible returned waypoint snap limit (<=250m from catalog), no geometry required. Bike profile must be explicitly supplied; do not assume driving is suitable. Reject public demo hostname router.project-osrm.org in configured service. Misconfiguration503, provider timeout/unreachable502, no route422. Amount per passenger = integer ceiling(distance_meters * mode_minor_per_km /1000), limit to safe integer and bounded maximum; no invented live pricing. Expose provenance/synthetic label.

## Offer transaction and canonical integration

Prevalidate shape/date/idempotency outside transaction. Transaction lock order: owner user -> membership -> owned car -> host application -> quote -> pickup rows sortedID -> canonical nodes sortedID. Recheck active user/member/configuredcollege/exact owned complete current approved fingerprint/mode. Quote must belong to caller and college; expiry and stop versions/active status/canonical node snapshots checked before first consumption. Serialize per-owner publications through user lock so same-key/different-key duplicate attempts converge. Idempotency is scoped to owner/key and normalized complete request, including description.

Use canonical TripsManager::create with server-built payload and exact car/points/date/seats/INR fare. Trust route metrics only through a request-scoped TrustedRouteContext matched to exact ordered points and reset in finally; it must never accept a client field or populate shared points-only RouteCache. Both manager preflight and repository call must see this quote. Preserve canonical validation, routes/path, passenger authority and lifecycle. The quoted seat fare must not be silently changed by legacy foreign pricing/caps; snapshot fare and canonical seat_price_cents must agree. Reject a canonical preexisting duplicate rather than bind a new quote to a different trip. All DB writes including points/routes, publication and quote consumption commit together; failure rolls back and quote stays usable. Do not request routing under locks. Avoid publishing external side effects before commit; flag any remaining canonical event/queue seam for review.

Legacy publish/update can otherwise bypass immutable quotes. Keep synthetic pilot clearly separate and testing-only; coordinator will restrict route/price changes for quote-backed canonical trips. No auth enhancement, provider account creation, public deployment or money movement in this packet.

## Required evidence

Routing: mode separation, exact catalog versions/canonical identity, no client metrics, missing config, no-route, timeout, malformed/huge/NaN metrics, non-2xx/redirect and excessive snap fail safely without quote/trip. Offer: wrong owner/mode/vehicle/expiry/changed stop, key replay/conflict, consumed quote, canonical rollback and exact DB fare/path, normal rider request/host accept/cancel using new Trip. Test fakes must be labeled synthetic; live road/profile suitability and physical devices remain separate acceptance work. Simultaneous retry requires actual concurrent DB evidence before claiming race proof.

## Discovery v1

GET `/api/mobility/pool-offers` is the bounded rider discovery path. Approved active members only; exclude own rides and show only quote-backed fixed-date canonical trips belonging to configured college with still-approved host/vehicle, planned lifecycle (absence means planned), nondeleted and `state=ready`. Required `service_date` valid local YYYY-MM-DD, today..today+30days; optional `from_time`/`to_time` HH:mm inclusive departure window; optional positive pickup_point_id/dropoff_point_id and vehicle_type. `page_size`1..50 default20, `after` positive tripID. Order by tripID ascending within service-date/window; pagination is current inventory, not a frozen snapshot. Unknown/array/malformed filters422; response `data` list plus next_cursor. Do not filter after LIMIT. Each item is a minimal DTO: id, from_town,to_town,trip_date (local YYYY-MM-DD HH:mm:ss),total_seats,seats_available (canonical accepted seats),vehicle_type,seat_price_minor,currency INR,synthetic_only,pickup_point_id,dropoff_point_id. No plate, legalidentity, contact, providerreference, reviewnotes or rawprivategeometry. Current exact vehicle approval applies; no live-suitability claim. Quotes' original expiry does not hide a legitimately published future trip. Discovery never reserves capacity. Existing canonical rider request/host acceptance remains the authority.
