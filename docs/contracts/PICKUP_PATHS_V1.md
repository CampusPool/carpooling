# Pickup path provider — V1 implementation seam

The existing fare/quote RouteProvider stays unchanged. New interface `STS\Mobility\Pickup\PathProvider::path(array $points, string $mode, float $timeoutSeconds = 5): array` takes2–8 ordered `{lat:float,lng:float}` points, modes `car|bike|foot`. It returns `distance_meters:int`, `duration_seconds:int`, `provider:'osrm'`, `profile:string`, `data_version:string`, `geometry:list<[lng,lat]>`, `waypoints:list<{distance_meters:float,location:[lng,lat]}>`, and `legs:list<{distance_meters:int,duration_seconds:int}>`. Geometry uses lon/lat, unsimplified GeoJSON LineString, ordered route direction. The provider is independent of booking/fare authority and performs no DB writes.

Use existing mode base/profile/expected_data_version config keys, plus explicit foot_base_url/foot_profile/foot_expected_data_version. Require strict mode-specific full crop/profile SHA identities (`foot|crop_sha256=<64hex>|profile_sha256=<64hex>` for walking). No synthetic or cross-mode fallback. Use configured trusted URLs only, reject credential/query/fragment/demo URLs, bounded connect2s/total5s/no redirects. Request `overview=full&geometries=geojson&steps=false&alternatives=false`, with radiuses250m motorized and50m foot. Bound points, response size<=2MiB, geometry2–20,000 finite valid pairs, totaldistance<=100km/duration<=86400s, waypointcount=pointcount, legcount=pointcount-1. Validate reported and calculated waypoint snap distances, geometry endpoints against snapped first/last waypoints, numeric finite metrics. Zero metrics allowed only for individual zero-length legs; a zero total route is valid only when all requested points coincide within1m, and cannot fabricate positive travel or walking.

Return RoutingException codes with no private payload/logged coordinates. Graph mismatch, malformed geometry/metrics/snaps, provider outage and NoRoute/NoSegment fail closed. Preserve metric raw validation before integer ceiling. Application candidate ranking compares actual pedestrian route distances, not geographic proximity. The pedestrian profile must optimize distance (not stock duration); its exact wrapper/hash and differential proof are independent inputs. Vehicle ETA and pedestrian speed assumptions remain uncalibrated.

The first pickup-preview service will use this seam to bind immutable driver-route and rider-origin revisions, produce direct detour plus best among bounded evaluated on-route candidates, and store expiring actor-scoped proposals. No canonical booking or existing accepted-route/fare change is authorized by a preview. Geometry is routing evidence, not proof of legal/safe stopping/crossing. Scheduled/recurring and on-demand canonical integration remain required next steps.

The optional timeout budget must be finite and in(0,5]seconds. Both connection and total transport timeout are capped to the supplied remaining budget. The planner has an overall20second monotonic deadline and checks before and after each provider operation. This is a bounded software preview computation, not a travel-time promise.
