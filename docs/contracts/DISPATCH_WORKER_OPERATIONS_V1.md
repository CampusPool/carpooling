# DISPATCH_WORKER_OPERATIONS_V1

20 October 2026. S5 continuation. Dispatch deadlines, offers and assignment remain authoritative in MySQL. Operational heartbeat files report process health only; they never decide a ride state. No external provider or public deployment is involved.

`mobility:dispatch-work --limit=20` remains one bounded pass. Add explicit `--watch --sleep=2 --max-cycles=0` for supervision; zero max-cycles means continue until signal/failure. Validate limit1..100, sleep1..10, max-cycles0..10000; reject unknown/invalid combinations without processing. SIGTERM/SIGINT finish the current transaction/cycle and stop before another. Failure returns nonzero with a sanitized event/code; never print query SQL, credentials or complete exception messages. Fail-fast supervision must expose persistent failure rather than reporting a healthy stuck worker.

A heartbeat at fixed default `/tmp/mobility-dispatch-worker.json` (trusted CLI/environment override allowed for tests) is atomically replaced after successful cycles. Fields: schema version, process ID, random instance ID, status, Unix UTC last-success timestamp, completed cycle count and last processed count. Starting/stopping/failure must not reuse an earlier healthy heartbeat. One exclusive lock per heartbeat path prevents two watch processes writing the same health record. Release handles in finally. No database migration is needed. `--health` reads/checks heartbeat state/age (max15seconds) live PID where supported, and a held lifetime lock (a released lock fails closed even if the numeric PID is reused), exits0 only for a current successful running worker, and never processes jobs. It cannot combine with watch or work options. Heartbeat is local operational data; a container restart creates a fresh instance/file.

Compose defines a separate `dispatch-worker` service under explicit profile `dispatch`: existing pinned PHP image, hardened vendor and extension mounts, testing-only local DB/config, no published ports, no dependency installer, restart unless-stopped, init enabled, stop grace period20seconds, read-only extension/vendor code, writable private tmpfs heartbeat. Resource limits target at most1CPU/256MiB. It shares the internal app network and existing MySQL, with no network needed for route/provider calls. App/pilot normal commands remain explicit; the coordinator owns Compose/start/stop/status scripts. Existing pilot down must stop this service while preserving the DB volume. A dedicated reversible local worker helper can start/status/stop only this worker against the already healthy synthetic pilot; it must not create/reset actor fixtures or migrations implicitly.

Evidence before claiming local operations: bounded one-shot regression; strict option validation; heartbeat healthy/stale/stopped and atomic file handling; graceful TERM; supervisor replacement after actual SIGKILL; database/offer/assignment recovery across restart; no duplicate/resurrected offers or assignments; blocked/failed DB work cannot remain healthy; no host ports or source/vendor mutation. A hard-kill while a real transaction is open requires explicit retained-DB rollback/readback, not just restarting an idle worker. Actual phone delivery, routing and external payments remain independent gates.
